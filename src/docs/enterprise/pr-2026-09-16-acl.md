# PR: feat(hub): role-based console API ACL overlay

## 问题 / Problem

多租户/委托运营的 hub 中，personal-runtime 代理面对所有 member 角色全量开放：
普通用户可以按路径触达 admin 面的 agent 端点、debug 面、应用生命周期写操作。
hub 侧此前没有任何「按角色 + 路径 + 方法」的策略层。

On multi-tenant or delegated hubs, the personal-runtime proxy exposes
every proxied path to any member role: a regular user can reach
admin-plane agent endpoints, debug surfaces, and app lifecycle writes
by path. The hub had no role x path x method policy layer.

## 方案 / Approach

- **新增 `src/qwenpaw/hub/acl/`**（纯增量，~533 行）：
  - `AclEngine`：正则路径 × 方法的规则求值，非 admin 角色**默认拒绝**；
  - `DEFAULT_RULES`：覆盖文档化的 member 面（chat、agent 读、审批、
    usage、tool-calls、marketplace 浏览、个人偏好），对 scoped-admin
    子树与生命周期写显式拒绝；
  - **运营覆盖层** `<hub root>/acl.json`（或 `QWENPAW_HUB_ACL_CONFIG`）：
    mtime 热重载，可扩展/收紧任意规则，无需重启；
  - `console_map`：角色 → 前端能力面板 payload。
- **`control_app.py`（+37 行）**：engine 挂载、`GET /api/hub/me/permissions`、
  `personal_runtime_proxy` 头部的 decide() 门——拒绝时
  `403 {code: ACL_DENIED, reason}` 并经 #7683 的审计发射器记录
  `acl.denied`（`outcome=denied`, `remote_address`）。
- **测试**：72 个 ACL 用例（引擎语义、覆盖层优先级、热重载、真实 app
  集成）+ 既有代理测试的探针路径移到 member 允许面。

## 兼容性 / Compatibility

**无 `acl.json` 时零行为变化**：admin 角色完全绕过门；member 保持文档化
面不变，仅对原本就不该访问的路径获得明确 403（带 reason）。

## 关联 / Related

- 与 #7683（审计发射器）互补：拒绝事件直接复用其 `outcome`/`remote_address` 参数。
- 与 #7696（本地管理员引导）正交：角色体系沿用 hub 既有 `user.role`。
